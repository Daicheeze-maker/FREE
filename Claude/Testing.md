# Testing

Back to [[Home]]

## Run the tests
```bash
cd backend
python tests/fetch_test_models.py         # once: ~150 MB of small real models into tests/models
python -m pytest                          # 32 tests (one long-video test takes ~1 min)
python -m pytest -m "not slow"            # skip the 10-minute-video test
```
Without the test models, the model-dependent tests are **skipped**, never faked. `CLIPFORGE_TEST_MODELS` can point to another folder.

## Fixtures
`backend/tests/fixtures/` (committed, ~1.5 MB), regenerated by `python tests/make_fixture.py` (needs FFmpeg with `flite`):
- `speech_scene.mp4` (42 s): synthesized speech (story, tip, question+answer, "wait, what was that?"), a noise burst at 35 s, scene cuts at 14 s and 26 s
- `no_audio.mp4`, `boring.mp4` (still image, near silence), `corrupted.mp4`

`make_fixture.py --laugh some_laughter.wav` adds real laughter at 9.5 s. The committed fixture has none, because the laughter sample used during development comes from a model's test set with unclear redistribution terms.

## What the suite covers
| Area | Tests |
|---|---|
| Import & metadata | real FFprobe values, corrupted file, unsupported type, duplicates, upload path sanitizing, failed uploads leave nothing behind |
| Audio | extraction, loudness, spike detection (and that starting to talk is *not* a spike) |
| Transcription | real Whisper output, language, sentence times inside the right window |
| Timestamps & captions | SRT/VTT/ASS formats, cue/word sync, trimming keeps sync, edited text keeps or rebuilds word timing, Tagalog preserved |
| Scenes & events | cut times exact, events at the right times |
| Clip engine | joke keeps setup + full laughter and excludes the next topic; no mid-sentence boundaries; no signal → no clips; weak → low confidence; loudness alone does not win |
| Reframing | stable lock on jitter, smooth tracking, jumps only on cuts, no face tracking on faceless gameplay, manual clamp |
| Rendering | real MP4 with manual crop, gaming style, edited caption, SRT sidecar; resolution/duration/codec checked with ffprobe; burned captions change the pixels; music loop + mute + blur-fit + 1:1 + 30 fps + loudnorm; silent video gets a silent audio track |
| Persistence | fresh app instance on the same data keeps clip edits, captions and exports; re-analysis keeps edited clips |
| Jobs | cancel then resume skips finished stages; restart marks running jobs interrupted, and retry works |
| Errors | missing speech model, YouTube URL validation, unreachable/unavailable video |
| Security | session required, foreign Origin/Host rejected, phone pairing PIN, secrets never returned |
| Long video | 10-minute video: candidates spread across the whole video |

## Verified by hand (browser automation, real app)
Import → analyze → results → preview → editor (gaming preset, manual crop, trim, caption text edit) → export → reopen in a new window: edits kept. The exported frame showed the edited caption in the gaming style and the right-side crop. Phone layout (390 px) checked for results and editor. Desktop shell launched on Linux: it starts the engine, opens the studio, and the engine exits even if the app is force-killed. The PyInstaller engine ran a full analysis and export.

## Test scenarios from the brief
| Scenario | Status |
|---|---|
| Short video with speech | automated |
| Long video | automated (10 min) |
| No audio | automated |
| Background music | detection is covered by the tagger's `music` kind; there is no dedicated music fixture |
| Multiple speakers | **not verified**: no diarization model is integrated, see [[Known Limitations]] |
| Tagalog speech, English/Taglish | caption/lexicon handling automated; **recognition accuracy not verified** (no real recordings in the build environment) |
| Nothing interesting | automated |
| Corrupted video | automated |
| Unsupported/unavailable YouTube URL | automated (the network to YouTube was blocked, so the error path is what was exercised) |
